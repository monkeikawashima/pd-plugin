# pd

**「たぶんこれが原因だと思う」を、「これが根拠です」に変える Claude Code の拡張機能です。**

プロダクトの数字が悪いとき、原因を思いつきで決めずに、データと利用者の声から順番にたどります。結論だけでなく、**何を根拠にそう考えたか**と、**何が起きたら考えを変えるか**まで文章で残ります。

---

## 誰のためのもの

| こんな人 | pd がやること |
|---|---|
| 数字が落ちた理由を聞かれて困っている | 原因の候補を分解して、確からしい順に並べる |
| 改善案は出るが、根拠が弱いと言われる | どの数字・どの声が根拠かを対応づけて書く |
| 分析するたびに前回の話が消える | 1回=1ファイルで残り、過去は書き換わらない |
| チームで判断がブレる | 「確認済み」と「まだ推測」を全文で区別する |

分析の専門知識は要りません。日本語で質問するだけです。

**向いていないこと**: コードを書く、UI 仕様を決める、進捗報告を作る。

---

## 使ってみる

**1. 入れる**（1回だけ）

```
/plugin marketplace add monkeikawashima/pd-plugin
/plugin install pd@pd-plugin
```

**2. 使うプロジェクトで準備する**（プロジェクトごとに1回だけ）

```
/pd-init
```

保存場所と自動チェックが用意されます。既にあるファイルは触りません。

**3. 更新の受け取り方を決める**（1回だけ）

**更新は放っておくと届きません。** Claude Code は、公式以外の配布元を既定で自動更新しないためです。次のどちらかを選んでください。

| | やり方 | 向いている場合 |
|---|---|---|
| **手動**（既定） | 下の「更新する」を必要なときに実行 | チームで使う。判定ルールが勝手に変わると困る |
| **自動** | `/plugin` → Marketplaces → pd-plugin → **Enable auto-update** | ひとりで使う。常に最新でよい |

自動にすると、セッション開始から10分以内に更新され、更新された旨が通知されます。

**4. 質問する**

```
/pd 申し込みが減っている理由を調べたい
```

## 更新する

```
/plugin marketplace update pd-plugin     配布元の一覧を取り直す
/plugin update pd@pd-plugin              plugin 本体を更新する
/reload-plugins                          今のセッションに反映する
```

**分析データは消えません。** 更新で入れ替わるのは plugin 側（分析の進め方・チェックの仕組み）だけで、プロジェクト側のファイルには触れません。

**更新すると何が変わるかは [CHANGELOG.md](CHANGELOG.md) にあります。** チェックのルールが変わった版では、今まで通っていたファイルが指摘されることがあります。

---

## 何が残るか

質問1回につき、Markdown ファイルが1つ増えます。中身はこうなります。

```
現状 → 問題 → 根拠 → 原因の候補 → 仮説 → 次に試すこと → 判断
                                        ＋ この結論が間違いだと分かる条件
```

過去のファイルは**書き換えません**。考えが変わったら新しく書き、前回との差分を残します。半年後に「なぜそう判断したか」を追えるようにするためです。

---

## いちばん大事な1つ

すべての文に、**どのくらい確かか**の目印が付きます。

| 目印 | 意味 |
|---|---|
| `Fact` | 実際に確認できた |
| `Interpretation` | そこから読み取れる |
| `Hypothesis` | まだ確かめていない |
| `Unknown` | 分からない |

読み取っただけのことを、後で「確認済み」として使わない。これだけで結論の危うさがかなり減ります。

---

## ルールは覚えなくていい

外れていたら機械が指摘します。人が覚えておく必要はありません。

```
作業開始 → 残っている問題を通知
書いた直後 → その場で指摘（直してから進む）
作業終了 → 残っている問題を通知
共有時   → 同じチェックが自動で走る
```

自分で確認したいときは `/pd-validate`。

**見ているもの**: 置き場所と名前 / 必要な項目 / **お客様の実名が残っていないか** / 元データが混ざっていないか / 過去の記録が書き換わっていないか。

---

## 3つの約束

1. **元データを置かない** — 表計算・書き出しファイル・画面の写真は置かず、集計した数値と取り方だけを残す
2. **名前を消してから残す** — 聞き取りの記録は、氏名・店名・連絡先を消す
3. **予測を事実と混ぜない** — 想定した回答は、確認できたこととは別扱いにする

なお、**プロダクトの情報はこの plugin には入りません。** plugin は更新のたびに上書きされるため、書き換えるものはプロジェクト側に置きます。

## 開発者向け

```bash
python3 scripts/validate.py     # 配布物が揃っているか
sh scripts/selftest.sh          # チェックの仕組みが本当に働くか
```

- `skills/` を変更したら `pd-skill-blueprint.md` の該当箇所も同じ作業内で更新する
- 判定を変えたら版を上げ、`CHANGELOG.md` に書く（書き忘れると `validate.py` が落とす）
