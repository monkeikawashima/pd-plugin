# pd — Product Discovery Skill

プロダクトの課題を、思いつきではなく**根拠から**たどるための Skill です。KPI・利用状況・声・実験結果を材料に、原因の候補を絞り、次に何を試すかと、何が起きたら考えを変えるかまでを書き残します。

Claude Code の plugin として配布しています。

## 入れる

```
/plugin marketplace add monkeikawashima/pd-plugin
/plugin install pd@pd-plugin
```

使いたいプロジェクトで、最初に1回だけ実行します。

```
/pd-init
```

置き場所・チェックの仕組み・ルールの説明が作られます。既にあるものは触りません。

## 使う

```
/pd 申し込みが減っている理由を調べたい
```

分析の結果は 1回 = 1ファイルとして残ります。過去のものは書き換えません。**判断が変わったときは、新しく書いて差分として残します。**

```
/pd-validate            ルールに外れたところを探す
```

## 何が入るか

| 場所 | 中身 |
|---|---|
| plugin 側 | 分析の進め方、判断の型、チェックの仕組み |
| プロジェクト側 | プロダクトの現状、分析の履歴、聞き取りの記録、予測 |

**プロダクトの情報は plugin に入りません。** plugin は更新のたびに上書きされるため、書き換えるものはプロジェクト側に置きます。

## いちばん大事な考え方

書いたことすべてに、**どの程度確かなのか**の目印を付けます。

| 目印 | 意味 |
|---|---|
| `Fact` | 実際に確認できたこと |
| `Interpretation` | そこから読み取れること |
| `Hypothesis` | まだ確かめていない考え |
| `Unknown` | 分からないこと |

読み取ったことを、後の場面で「確認できたこと」として使わない。これだけで、結論の危うさがかなり減ります。

## 間違いは自動で見つかります

ルールを覚える必要はありません。外れたものは機械が指摘します。

```
① 作業を始めたとき   → 残っている問題が通知されます
② ファイルを書いた直後 → その場で指摘され、直してから先に進みます
③ 作業の終わり       → 残っている問題が通知されます
④ 変更を共有したとき   → 同じチェックがもう一度、自動で走ります
```

見られるのは、置き場所と名前、必要な項目が書かれているか、**お客様の名前が残っていないか**、元データが混ざっていないか、過去の記録が書き換わっていないか、などです。

## 約束

- 元データ（表計算・書き出したファイル・画面の写真）を置かない。残すのは集計した数値と、その取り方
- 聞き取りの記録は、名前・店名・連絡先を消してから残す
- 予測は予測として扱い、確認できたことと混ぜない

## 開発

```bash
python3 scripts/validate.py     # 配布物が揃っているか
sh scripts/selftest.sh          # チェックの仕組みが本当に働くか
```

`skills/` を変更したら `pd-skill-blueprint.md` の該当箇所も同じ作業内で更新してください。
