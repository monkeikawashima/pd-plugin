# ux-research-planner — 探索の設計

**`ux-validation-planner` と対になるスキル。**

| | このスキル（探索） | `ux-validation-planner`（検証） |
|---|---|---|
| 段階 | まだ仮説が無い | 仮説がある |
| 問い | 何が起きているのか | この仮説は棄却されるか |
| 失敗 | 何も新しく分からない | 仮説の採否が決まらない |
| 出口 | 台帳に声が増える → 仮説が立つ | 仮説が採用/棄却される |

**探索を検証のやり方でやると、知りたかったことが最初から答えの中に無い。**

## 役割分界（重複させない）

| このスキルがやること | やらないこと（担当スキル） |
|---|---|
| 「何を見に行くか」の決定 | 仮説の採否を決める設計（`ux-validation-planner`） |
| 観察・インタビューの計画 | 逐語の記録そのもの（`user-voice-ledger`） |
| **聞かないこと**の明示 | 利用者像の集計（`user-persona-builder`） |
| 打ち切り条件（飽和）の設定 | 数値指標の継続計測（`ux-measurement`） |
| — | 決定の記録（`ux-decision-record`） |

## 事前に決めること（**人間が決める。ここで停止する**）

| 項目 | 決める人 |
|---|---|
| 対象者の人数・役割 | 人間 |
| 実施時期 | 人間 |
| 実施者・記録者 | 人間 |
| 対象者への謝礼・同意の取り方 | 人間 |

**「5人程度」などと埋めない。** 未定なら「未定」と書き、**決める人と期限**を添える。

## 手順

### 1. いま何が分かっていないかを先に書く

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/voices.mjs" stats
```

| 見るところ | 意味 |
|---|---|
| `speaker_role` の偏り | **声が0件の系統**。そこは「問題が無い」ではなく「見ていない」 |
| `screen` の偏り | 誰も何も言っていない画面 |
| `type` の偏り | `positive` が0件なら、壊してはいけないものが分かっていない |

> ⚠️ **最も重要な偏りは、離脱者と非利用者の不在。**
> 使い続けている人だけに聞くと、辞めた理由は永久に出てこない。

### 2. 見に行くことを決める（**問いではなく、見る対象**）

| 決めるもの | 例 |
|---|---|
| 誰の | どの系統の、どういう状況の人か |
| どの場面を | 何をしようとしているところか |
| どうやって | 行動観察 / 作業の実演 / 直近の実体験の想起 |

**意見ではなく行動を見る。** 「どう思いますか」で得られるのは、その場で作られた意見。

### 3. **聞かないこと**を先に決める（**この節を省略しない**）

探索で最も多い事故は、答えを自分で言ってしまうこと。

| 聞かない | なぜ |
|---|---|
| 「◯◯機能があったら使いますか」 | ほぼ全員が「使う」と答え、何も分からない |
| 「この画面、分かりやすいですか」 | 目の前の相手を否定しにくい |
| 「なぜ使わないんですか」（詰問形） | 理由が後付けで作られる |
| こちらの用語 | 相手の言葉が失われる。**相手が使った語をそのまま使う** |

代わりに聞くのは、**直近の実体験**（「最後にそれをやったのはいつですか。そのとき何をしましたか」）。

### 4. 打ち切り条件を決める

**「何人聞くか」ではなく「何が起きたら止めるか」。**

| 打ち切り | 条件 |
|---|---|
| 飽和 | 連続 <n> 人で新しい論点が出なくなった |
| 打ち切り | 予定した人数・時期に達した（**新しい論点が出続けていてもここで止め、続きを起票する**） |

飽和せずに終わった場合は「**飽和していない**」と明記する。**足りたことにしない。**

### 5. 記録の流し先を決める

得られた発話は**逐語のまま** `user-voice-ledger` へ渡す。

- 要約してから渡さない（一次情報が失われる）
- その場で解釈しない（解釈は `[推測]` を付けて後で書く）
- 匿名化してから記録する

### 6. 書く

`skills/analyze/uiux/templates/research-plan.md` を Schema として
`pd/validations/{プロダクト}/{年}/RP-YYYYMMDD-NN-{主題1語}.md` に書く（追記のみ）。

> 検証計画（`VP-`）と同じ置き場所で、接頭辞だけを分ける。
> **探索と検証は別物だが、置き場所を分けると片方が忘れられる。**

### 7. 終わったら渡す

| 出てきたもの | 次のスキル |
|---|---|
| 逐語 | `user-voice-ledger` |
| 系統ごとの像が見えてきた | `user-persona-builder` |
| 一意に決まらない論点 | `ux-validation-planner` |
| 上流の前提が崩れた | `ux-update-cascade` |
| 決めた / 決めなかった | `ux-decision-record` |

## 出力形式

```
■ 分かっていないこと: <一覧>（voices の偏りから）
■ 見に行く対象: <誰の / どの場面を / どうやって>
■ 聞かないこと: <一覧>（**空にしない**）
■ 打ち切り条件: 飽和（連続 <n> 人で新しい論点なし）/ 予定到達
■ 対象者: <人数・役割>（未定なら「未定」＋決める人＋期限）
■ 実施時期: <…>（未定可）
■ 実施者・記録者: <…>（未定可）
■ 記録先: pd/voices/（逐語）/ pd/validations/{プロダクト}/{年}/RP-…（計画）
```

## 禁止

- 対象者・時期・実施者を、こちらで決めて埋める
- 「聞かないこと」を書かずに実施する
- 意見だけを集めて行動を見ない
- 逐語を要約してから台帳に渡す
- 飽和していないのに「十分聞けた」と書く
- 使い続けている人だけに聞いて、離脱者の不在を書かない
