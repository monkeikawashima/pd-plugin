# a11y-contrast-guard — コントラスト検算

**このレーンは上流の決着に依存しない唯一のレーン。** 他層の合意を待たずに進められる。

## 役割分界（重複させない）

| このスキルがやること | やらないこと（担当スキル） |
|---|---|
| WCAG 検算と下限値の算出 | UI 全体の評価（`ux-design-review`） |
| 色だけに依存した状態表現の検出 | 採用色の最終決定（**DESIGN の領域**） |
| 逸脱表への追記 | 例外の記録（`ux-decision-record`） |
| — | トークン台帳の所有（`design-token-keeper`） |
| — | 操作の検査（キーボード・読み上げ・寸法・動き）（`a11y-interaction-guard`） |

## 基準値（WCAG 2.1 AA）

| 対象 | 基準 |
|---|---|
| 通常テキスト | **4.5:1** |
| 大きいテキスト（18pt 以上 / 14pt 太字以上） | **3:1** |
| 非文字要素（境界線・アイコン・入力枠・フォーカスリング） | **3:1** |
| **プレースホルダー** | **4.5:1**（入力前の唯一の手がかりのため通常テキスト扱い） |

## 手順

### 1. 対象と用途を特定する

テキストか、非文字要素か、プレースホルダーか。**用途で基準が変わる。**

### 2. 現在値を計算する

相対輝度 L から:

```
contrast = (L_lighter + 0.05) / (L_darker + 0.05)
```

> ⚠️ **`oklch()` などの色空間関数は、実ビルド出力の hex で検算する。**
> 手計算の近似は基準の境界付近で合否が変わる。
> ソースの値ではなく**ビルド後の出力 CSS** から `--<変数名>` の hex を取る
> （取り方はプロジェクトのビルド構成による）。
> **取れなければ「実測できていない」と書く。近似値で合否を判定しない。**

背景が重なる場合（半透明・グラデーション・画像上）は、**最も不利な組み合わせ**で計算する。

### 3. 満たさない場合、色相を変えずに輝度だけ動かす

色相（hue）と彩度（chroma）を保ち、**明度だけ**を動かして基準を満たす最小値を求める。
色相ごと変えるのはデザインの判断であり、このスキルの領域ではない。

### 4. 下限として提示する

```
現在 3.8:1 → 基準 4.5:1 を満たさない。
色相を保ったまま満たす下限: <値>（コントラスト 4.52:1）
これは「ここまでは必要」という下限であり、採用色の決定は DESIGN が行う。
```

### 5. 状態表現を点検する

成功・警告・エラー・無効・選択中を**色の違いだけ**で表現していないか。
文字・形・アイコン・位置のいずれかを併用しているか。

### 6. 記録する

逸脱は `pd/specs/05-surface/design-tokens.md` の表に追記する。
例外として残す場合は `ux-decision-record` へ（**棄却条件＝いつ直すか を必ず付ける**）。

## 出力形式

```
■ 対象: <画面 / 要素>
■ 用途: 通常テキスト / 大きいテキスト / 非文字要素 / プレースホルダー
■ 前景 / 背景: <hex> / <hex>（取得元: トークン定義 / ビルド出力）
■ 現在値: n.nn:1
■ 基準: 4.5:1 / 3:1
■ 判定: 満たす / 満たさない
■ 下限値の候補（色相維持）: <hex>（n.nn:1）
■ 状態表現の所見: 色以外の手がかり <あり（文字/形/位置） / なし>
■ 記録先: pd/specs/05-surface/design-tokens.md
■ 最終決定: DESIGN（このスキルは下限までしか出さない）
```

## 禁止

- 目分量・印象で「十分見える」と判定する
- `oklch()` の値を手計算の近似で判定する
- 採用色を指定する（下限までにとどめる）
- プレースホルダーを 3:1 で許容する
- 状態を色だけで区別したまま通す
- フォーカスリングを、代替演出なしで除去したまま通す
