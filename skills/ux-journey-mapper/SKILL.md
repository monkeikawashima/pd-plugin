# ux-journey-mapper — 時間軸の分解

**5層は静的な断面であり、時間軸を持たない。** ジャーニーがその欠けている軸を埋める。

**ジャーニーの絵を描くことが目的ではない。**
ステップの分解は、そのまま `ux-measurement` の主要タスク時間の構成要素になる。

```
<主要タスク時間> = <ステップ1> + <ステップ2> + <ステップ3>
```

**この右辺とジャーニーのステップを別々に管理しない。** 二重に持つと必ず食い違う。

## 役割分界（重複させない）

| このスキルがやること | やらないこと（担当スキル） |
|---|---|
| ステップへの分解と時間軸の設計 | 層の判定（`ux-layer-triage`） |
| 主要タスク時間の構成要素との対応づけ | 実測値の取得と報告（`ux-measurement`） |
| 詰まり・離脱の位置の特定 | 画面の中身の設計（`ux-screen-spec-writer`） |
| 各ステップの根拠ボイスの引き当て | 逐語の記録（`user-voice-ledger`） |
| — | 対象者の像（`user-persona-builder`） |
| — | 検証の実施設計（`ux-validation-planner`） |

## 最初に読む

| ファイル | 何のために |
|---|---|
| `pd/specs/01-strategy/personas.md` | 誰のジャーニーか（1系統 = 1本） |
| `pd/specs/01-strategy/kpi.md` | 主要タスク時間の定義と構成要素 |
| `pd/specs/02-requirements/user-stories.md` | 各ステップに対応するストーリー |
| `pd/specs/03-structure/object-model.md` | ステップで触る対象物の名前 |

## 手順

### 1. 単位を決める

**1ペルソナ × 1主要タスク = 1本。**
系統をまたいだ「代表的な流れ」を1本にまとめない。誰の詰まりか分からないまま合意が成立する。

対象ペルソナが `personas.md` に無い、または確信度が「未取得」なら、
**ジャーニーを描く前に `user-persona-builder` へ戻る**（誰のものか分からない流れは検証できない）。

### 2. ステップに分解する

分解の粒度は「**そこで手が止まりうる単位**」。画面の枚数ではない。
1画面の中に2つの停止点があるなら、ステップは2つになる。

各ステップに次を持たせる。

| 列 | 中身 | 埋められないとき |
|---|---|---|
| ステップ名 | 主要タスク時間の構成要素と**同じ語** | kpi.md 側を先に直す |
| 担う画面・接点 | 画面名（`voices` の `screen` と同じ表記） | 「未設計」 |
| 触るオブジェクト | `object-model.md` にある名前のみ | 構造層へ戻る |
| 対応ストーリー | `US-xx` | 「未起票」 |
| 根拠 | `VOICE-xxx`。**0件なら「一次情報なし」** | 空欄にしない |
| 所要時間 | 実測値、または **未取得** | それらしい数字を置かない |
| 詰まり・離脱 | 観測された事実 / `[推測]` を付けた解釈 | 「未観測」 |

### 3. 裏側（任意）

利用者が待っている間、**裏で誰が何をしているか**が改善余地の本体になることがある。
必要な場合だけ、各ステップに次の2行を足す（不要なら足さない）。

| 行 | 中身 |
|---|---|
| 表側の接点 | 利用者から見えているもの |
| 裏側の処理 | 見えないところで動いている人・処理・待ち |

**裏側の行を足したら、そこにも所要時間の欄を持たせる。** 待ちは利用者の時間を消費している。

### 4. 空白を数える

ステップの中で、次のどれかに当てはまるものを数えて明示する。

| 空白 | 意味 |
|---|---|
| 根拠が「一次情報なし」 | このステップの設計は**デザイナー起案** |
| 所要時間が「未取得」 | 改善したと**言えない**区間 |
| 担う画面が「未設計」 | 骨格層への申し送り |

> **空白の数を報告する。** 埋まっているところだけを見せると、全体が検証済みに見える。

### 5. 書く

`skills/analyze/uiux/templates/journey.md` を Schema として
`pd/specs/02-requirements/journeys.md` に**上書き**する（現在値）。

複数本ある場合は同じファイル内に見出しを分けて並べる。**索引ファイルを作らない。**

### 6. 渡す

| 出てきたもの | 次のスキル |
|---|---|
| 所要時間が未取得の区間 | `ux-measurement` |
| 画面が未設計のステップ | `ux-screen-spec-writer` |
| どちらの流れが良いか決まらない | `ux-validation-planner` |
| 対象物が足りない | `object-model-reviewer` |
| 上流（ペルソナ・原則）が変わった | `ux-update-cascade` |

## 出力形式

```
■ 対象ペルソナ: <呼称>（確信度: 実証 / 作業仮説）
■ 主要タスク: <kpi.md の定義と同じ語>
■ 分解式: <主要タスク時間> = <ステップ1> + <ステップ2> + …
■ ステップ数: <N>
■ 空白: 一次情報なし <n> 件 / 所要時間 未取得 <n> 件 / 画面 未設計 <n> 件
■ 詰まりの候補: <ステップ名>（観測 / [推測]）
■ 記録先: pd/specs/02-requirements/journeys.md
■ 次のアクション: <スキル名>
```

## 禁止

- 主要タスク時間の構成要素と別の語でステップを立てる（二重管理になる）
- 所要時間に、それらしい数字を置く（未取得と書く）
- 末尾の1ステップだけを縮めて「主要タスクが速くなった」と言う
- ペルソナ未定義のままジャーニーを描く
- 系統をまたいだ1本にまとめる
- 根拠の欄を空欄で残す（「一次情報なし」と書く）
