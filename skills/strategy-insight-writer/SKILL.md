# strategy-insight-writer — 戦略層の言語化

**5層の上端。ここが空だと、下流のすべてが「好み」になる。**

`ux-layer-triage` の R1（コンセプト還元テスト）は、このスキルの成果物が無いと**実施不能**になる。
実施不能のまま下流を進めること自体は許されるが、その状態を**黙って**進めることは許されない。

## 役割分界（重複させない）

| このスキルがやること | やらないこと（担当スキル） |
|---|---|
| インサイト・コンセプト・ポジショニングの起草 | 層の判定（`ux-layer-triage`） |
| コンセプトの要素分解と採番 | 利用者像の集計（`user-persona-builder`） |
| 一次情報インベントリの整備 | KPI の定義とベースライン取得（`ux-measurement`） |
| 「相場」と「差別化」の切り分け | 要件化（`user-story-writer`） |
| — | 決定の記録（`ux-decision-record`） |
| — | 検証の実施設計（`ux-validation-planner`） |

## 最初に読む

| ファイル | 何のために |
|---|---|
| `pd/specs/00-status.md` | どの層まで成果物があるか |
| `pd/specs/01-strategy/glossary.md` | 使ってよい呼称 |
| `pd/specs/01-strategy/personas.md` | 誰のためかの根拠（あれば） |
| `pd/specs/01-strategy/evidence-inventory.md` | 引ける一次情報とその取得時期 |

## 手順

### 1. 一次情報インベントリを先に整える

**ここに載っていないものを根拠に引かない。**
`pd/specs/01-strategy/evidence-inventory.md` に、引ける一次情報を1行ずつ並べる。

| 一次情報 | 取得時期 | 取得方法 | 効く層 | 備考（件数・偏り） |
|---|---|---|---|---|

取得時期の無い行は使えない。**半年前の声と昨日の声を同じ重みで扱わないため。**
1行も無ければ「**一次情報インベントリが空**」と宣言し、以降の記述すべてを作業仮説として扱う。

### 2. インサイトを書く

インサイトは「事実」ではなく「**事実から読み取った、まだ広く共有されていない見方**」。
1件ごとに次を揃える。

| 欄 | 中身 |
|---|---|
| 見方 | 一文。`[推測]` を付ける（検証を通るまでは解釈） |
| 元になった事実 | `VOICE-xxx` / 計測値 / 実査。**出典なしの行を書かない** |
| これが正しいと何が変わるか | 下流のどの判断が動くか |
| 棄却条件 | 何が観測されたらこの見方を捨てるか（観測可能な閾値で） |

### 3. コンセプトを要素に分解して番号を振る

`pd/specs/01-strategy/concept.md` に、コンセプト文と**番号付きの要素**を書く。

```
コンセプト: <一文>

C1. <要素>
C2. <要素>
C3. <要素>
```

> **番号を振るのは、下流から一文で参照できるようにするため。**
> 番号が無いコンセプトは、還元テストで「なんとなく効いている」を許してしまう。

### 4. ポジショニングを「相場」と「差別化」に分ける

| 分類 | 意味 | 扱い |
|---|---|---|
| **A. 相場** | 無いと選ばれないが、有っても選ばれない | 揃える。差別化の根拠にしない |
| **B. 差別化** | これがあるから選ばれる | コンセプトの要素と対応づける |
| **C. 賭け** | 効くかどうか分かっていない | **作業仮説**。棄却条件を付ける |

> 「競合にあるから欲しい」は**必ず A**。A を B として記録した時点で、戦略層は機能しなくなる。

### 5. 書けないところは停止する

| 状況 | 書き方 |
|---|---|
| 一次情報が無い | 「未取得」。**それらしい市場像を書かない** |
| 調べたが見つからない | 「<調査範囲> では確認できなかった」 |
| 公開ベンチマークが存在しない | 「ベンチマーク不在。自社ベースラインで測る」 |

### 6. 変えたら連鎖させる

コンセプト・ポジショニング・インサイトの変更は**戦略層の変更**。
下流（要件・構造・骨格・表層）すべてが再検証の対象になる → `ux-update-cascade`。

## 出力形式

```
■ 一次情報インベントリ: <行数> 件（空 / 有）
■ インサイト: <件数>（うち検証済み <n> / 作業仮説 <n>）
■ コンセプト要素: C1 〜 C<n>
■ ポジショニング: A(相場) <n> / B(差別化) <n> / C(賭け) <n>
■ 未取得のまま置いたもの: <一覧>
■ 記録先: pd/specs/01-strategy/
■ 次のアクション: <スキル名>
```

## 禁止

- 一次情報の裏づけが無い主張を、作業仮説と明示せずに書く
- コンセプトに番号を振らない（下流が参照できなくなる）
- 「競合にあるから」を差別化（B）として記録する
- 公開ベンチマークの不在を、それらしい平均値で埋める
- 利用者像を、ここで創作する（`user-persona-builder` が台帳から集計する）
