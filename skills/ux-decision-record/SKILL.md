# ux-decision-record — UXDR

**全工程から呼ばれる横断スキル。他のスキルは判断し、このスキルは記録する。**

## 役割分界（重複させない）

| このスキルがやること | やらないこと（担当スキル） |
|---|---|
| 決定・未決定・作業仮説の記録 | 判断そのもの（各層のスキル） |
| ステータス変更の記録 | 生の声の保存（`user-voice-ledger`） |
| `00-status.md` の更新確認 | 下流への連鎖実行（`ux-update-cascade`） |

## 記録する場面

- 何かを**決めた**とき
- 何かを**決められなかった**とき ← **これを落とさない**
- 作業仮説を置いたとき
- 仕様を変更したとき
- 「これで進めます」と合意したとき

## 手順

1. `skills/pd/uiux/templates/uxdr.md` をコピーする
2. ファイル名: `pd/decisions/UXDR-YYYYMMDD-NN-<slug>.md`（`NN` は同日内の連番）
3. 埋める
4. `pd/specs/00-status.md` を更新したか確認する

## 書き方のルール

### 決めなかったことを必ず書く

| 未決定の論点 | 何が分かれば決まるか | いつまでに | 誰が |
|---|---|---|---|

**3列すべて埋まらない未決定は、未決定ですらない。**「保留」とだけ書かない。

> 決められないことを認めるのは後退ではない。
> **「何が分かれば決まるか」まで特定できていれば前進。**

### 根拠は3種類だけ

| 種別 | 例 |
|---|---|
| 一次情報 | `VOICE-xxx` |
| 上位層の成果物 | `pd/specs/…` |
| 計測値 | `pd/measurements/MP-…` |

**計測値が無ければ「未取得」と書く。** 空欄にしない。それらしい数字を置かない。

### 作業仮説には棄却条件

`kind: 作業仮説` のとき必須。**棄却条件のない仮説は記録しても意味がない。**

### 影響範囲には「変わらなかったもの」も書く

## 出力形式

```
■ ファイル: pd/decisions/UXDR-YYYYMMDD-NN-<slug>.md
■ 層 / 区分: <層> / <決定 | 未決定 | 作業仮説 | 棄却>

■ 決めたこと
   - …

■ 決めなかったこと
   | 論点 | 何が分かれば決まるか | いつまでに | 誰が |

■ 根拠: 一次情報 <VOICE-xxx / なし> / 上位層 <spec> / 計測値 <値 or 未取得>
■ コンセプト還元: <一文 / 実施不能（上流が空）>
■ 棄却条件: <作業仮説のとき必須>
■ 影響範囲: 下流 <spec> / 変わらなかったもの <spec>

■ ステータス更新
   - [ ] pd/specs/00-status.md を更新した
   - [ ] 影響のある spec に 要再検証 を付けた
```

## 禁止

- 決めたことだけ書いて終わる
- 「保留」「あとで決める」だけの未決定
- 棄却条件のない作業仮説
- 根拠の欄を空にする（無いなら「なし」「未取得」と書く）
- spec のステータスを AI が勝手に昇格・差し戻しする（提案までにとどめる）
