# ia-navigation-reviewer — 到達可能性の点検

**「機能はあるのに使われない」の多くは、機能の問題ではなく到達経路の問題。**

構造層（何を対象物として扱うか）は決まっているのに、
骨格層（画面のどこに何を置くか）に落ちる前の**並べ方**には、これまで担当が無かった。

## 役割分界（重複させない）

| このスキルがやること | やらないこと（担当スキル） |
|---|---|
| ナビ項目と対象物・ステップの対応づけ | 新規オブジェクトの新設（`object-model-reviewer`） |
| 到達経路の確定（**どの入口から辿り着くか**） | 画面の中身の設計（`ux-screen-spec-writer`） |
| 階層の深さと分類軸の点検 | 時間軸の分解（`ux-journey-mapper`） |
| 迷子（どこからも辿り着けない画面）の検出 | 文言の点検（`ux-writing-guard`） |
| — | 実装済み UI の評価（`ux-design-review`） |

## 最初に読む

| ファイル | 何のために |
|---|---|
| `pd/specs/03-structure/object-model.md` | ナビ項目に使える対象物の名前 |
| `pd/specs/03-structure/core-objects.md` | このフェーズのコアは何か |
| `pd/specs/02-requirements/journeys.md` | 各ステップがどこから始まるか |
| `pd/specs/04-skeleton/navigation.md` | 既存のナビ構造（あれば） |

## 手順

### 1. 項目を対応づける（**対応が無いものは追加しない**）

ナビゲーションの各項目は、次のどちらかに必ず対応する。

| 対応先 | 意味 |
|---|---|
| **対象物** | 利用者が扱う「もの」の入口（一覧・詳細） |
| **ジャーニーのステップ** | 何かをする「動作」の入口 |

> ⚠️ **どちらにも対応しない項目は、誰の関心でもない。**
> 追加せず、`object-model-reviewer` か `ux-journey-mapper` へ戻す。
> 「その他」「設定」の下に置いて済ませない（そこは、決めなかったものの置き場になる）。

### 2. 到達経路を書く（**省略しない**）

各画面について、**どの入口から辿り着けるか**を並べる。

| 画面 | 到達経路 | 深さ |
|---|---|---|
| | 入口 → … → この画面 | |

| 見つかるもの | 意味 |
|---|---|
| 到達経路が**0本** | **迷子**。リンクを直接叩かないと辿り着けない |
| 到達経路が**1本だけ**で、それがコアの動線から外れている | 実質「無い」のと同じ |
| 到達経路が**多すぎる** | 分類軸が重なっている（同じものが複数の場所にある） |

### 3. 分類軸を1つに保つ

同じ階層に、**違う軸で分けた項目を混ぜない**。

```
✗ 対象物 / 対象物 / 動作 / 部署名   ← 軸が3つ混ざっている
◯ 対象物 / 対象物 / 対象物         ← 軸が1つ
```

軸を増やしたくなったら、それは**構造層の話**。`object-model-reviewer` へ戻す。

### 4. 深さを数える

| 見るところ | 判断 |
|---|---|
| コアへの深さ | **このフェーズのコアには最短で着けているか** |
| 使用頻度と深さの逆転 | よく使うものが深い位置にある |
| 1項目しかない階層 | その階層は要らない |

> ⚠️ **「浅ければ良い」ではない。** 全部を1階層に並べると、探す対象が増えて遅くなる。
> 判断基準は深さの数値ではなく、**コアへ最短で着けているか**。

### 5. 決まらないものは等価に並べる

分類が一意に決まらないときは、案を等価に置く（1案だけ書くと、書いた人の好みが既定値になる）。

| 案 | 分類 | 前提（この案が正しくなる条件） | 棄却条件 |
|---|---|---|---|
| A | | | |
| B | | | |

**＋「何を計測すれば決まるか」**（例: どの入口から辿り着いているか / 探し始めてから着くまでの時間）。

### 6. 書く

`skills/analyze/uiux/templates/navigation.md` を Schema として
`pd/specs/04-skeleton/navigation.md` に**上書き**する（現在値）。

### 7. 渡す

| 出てきたもの | 次のスキル |
|---|---|
| 対応する対象物が無い | `object-model-reviewer` |
| 対応するステップが無い | `ux-journey-mapper` |
| 等価案が残った | `ux-validation-planner` |
| 到達までの時間を測りたい | `ux-measurement` |
| 項目名が用語集と違う | `ux-writing-guard` |

## 出力形式

```
■ 項目数: <n>（対象物 <n> / ステップ <n> / 対応なし <n> ← **上流へ戻す**）
■ 迷子（到達経路0本）: <画面名 一覧>
■ 分類軸: 1つ / 混在（<混ざっている軸>）
■ コアへの深さ: <n> 段（コアオブジェクト: <名前>）
■ 頻度と深さの逆転: <一覧>
■ 決まらない分類: 等価案 A・B（計測項目: <…>）
■ 記録先: pd/specs/04-skeleton/navigation.md
```

## 禁止

- 対象物にもステップにも対応しない項目を追加する
- 到達経路を書かないまま項目を増やす
- 「その他」「設定」の下を、決めなかったものの置き場にする
- 同じ階層に違う軸を混ぜる
- 決まらない分類を1案だけ書く
- 深さの数値だけで良し悪しを判定する
