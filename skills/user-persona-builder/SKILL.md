# user-persona-builder — 利用者像の集計

**ペルソナは書くものではなく、集計するもの。**
創作したペルソナは、以後のすべての判断の根拠として流通し、誰も検証しないまま固定される。

## 役割分界（重複させない）

| このスキルがやること | やらないこと（担当スキル） |
|---|---|
| 台帳からの系統別集計と人物像の組み立て | 層の判定（`ux-layer-triage`） |
| 根拠件数・確信度・非対象の明示 | 逐語の記録（`user-voice-ledger`） |
| 「未取得」の宣言と停止 | 要件化（`user-story-writer`） |
| 系統ごとの主要タスクの紐づけ | 主要タスク時間の計測（`ux-measurement`） |
| — | 検証の実施設計（`ux-validation-planner`） |
| — | 決定の記録（`ux-decision-record`） |

## 最初に読む

| ファイル | 何のために |
|---|---|
| `pd/specs/01-strategy/glossary.md` | 利用者の呼称（ここで決めた語以外を使わない） |
| `pd/voices/taxonomy.json` | 集計の単位になる `speaker_role` の一覧 |
| `pd/specs/01-strategy/personas.md` | 既存の像との突合（あれば） |
| `pd/specs/01-strategy/evidence-inventory.md` | 引ける一次情報の範囲と取得時期 |

> ⚠️ **記憶で書かない。** 呼称も件数も、必ずファイルとコマンドの出力から取る。

## 手順

### 1. 集計の単位を確かめる

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/voices.mjs" stats
```

`speaker_role` が `taxonomy.json` に列挙されていなければ、**先に呼称を決める**。
決まっていない状態で集計すると、表記ゆれの数だけ人物像が増える。

### 2. 系統ごとに引き当てる

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/voices.mjs" query --speaker_role <役割>
```

引けた件数 `n` と、**最古〜最新の `captured_at`** を控える。
半年前の声と昨日の声を同じ重みで扱わないため、期間は必ず添える。

### 3. 確信度を決める

| 確信度 | 条件 |
|---|---|
| **実証** | 検証（VP-…）を1回以上通っている、または独立した5件以上のボイスで同じ関心が繰り返し現れる |
| **作業仮説** | ボイスはあるが検証を通っていない。**棄却条件を必ず付ける** |
| **未取得** | `n = 0`。**像を書かない**。「この系統の一次情報は未取得」とだけ書いて停止する |

> `n = 0` の系統を空欄で埋めない。**空欄は「居ない」ではなく「見ていない」。**

### 4. 書く

`skills/analyze/uiux/templates/persona.md` を Schema として
`pd/specs/01-strategy/personas.md` に**上書き**する（現在値であり、履歴ではない）。

1系統 = 1ペルソナ。系統をまたいだ「代表的なユーザー像」を1つにまとめない。

### 5. 変わったら連鎖させる

ペルソナの追加・確信度の変更・非対象の変更は**戦略層の変更**。
`ux-update-cascade` のトリガー A（新しい利用者層が入る）に該当する。

## 持たせる項目（テンプレートの必須欄）

| 欄 | 中身 | 埋められないとき |
|---|---|---|
| 呼称 | `speaker_role` と1対1。新語を作らない | glossary に戻る |
| 根拠件数 | `n = 12（2026-01 〜 2026-08）` の形 | `n = 0` なら「未取得」 |
| 確信度 | 実証 / 作業仮説 / 未取得 | — |
| 主要タスク | この系統の主要タスク時間（`ux-measurement` の定義と同じ語） | 「未定義」と書く |
| 関心・ペイン | **1行につき最低1つの `VOICE-` を添える** | 出典なしの行を書かない |
| 効いている点 | positive のボイス。**壊してはいけないもの** | 「未取得」 |
| 非対象 | **この像に含めない人**と、その理由 | 「未定義」と書く |
| 棄却条件 | 確信度が作業仮説のとき必須。観測可能な閾値で書く | — |

## 持たせない項目（**書かない**）

- 年齢・性別・居住地・家族構成・年収・趣味・休日の過ごし方・顔写真
- 「◯◯さん」のような固有名（台帳の匿名化を戻すことになる）

理由は2つ。①**プロダクトの判断に効かない**。②検証されていない断定が、検証済みの記述と同じ見た目で混ざる。
人物像に厚みが必要なら、装飾ではなく**逐語（`VOICE-`）を増やす**。

## 出力形式

```
■ 集計元: pd/voices/{プロダクト}/  （speaker_role = <役割>）
■ 件数: n = <件>（<最古> 〜 <最新>）
■ 確信度: 実証 / 作業仮説 / 未取得
   （作業仮説の場合）棄却条件: <観測可能な閾値>
■ 主要タスク: <ux-measurement の定義と同じ語 / 未定義>
■ 非対象: <この像に含めない人と理由 / 未定義>
■ 記録先: pd/specs/01-strategy/personas.md
■ 連鎖: ux-update-cascade を呼ぶ必要があるか（有 / 無）
```

## 禁止

- 台帳を引かずにペルソナを書く
- `n = 0` の系統に像を書く（「たぶんこういう人」は仮説ですらない）
- 装飾属性を足す
- 系統をまたいだ1つのペルソナにまとめる（誰の不便か分からなくなる）
- 確信度・非対象の欄を空のまま残す
