# design-token-keeper — 表層の台帳

**表層の成果物は「トークン」と「逸脱一覧」の2つ。** その両方をこのスキルが所有する。

**値を決めるのは DESIGN。** このスキルがやるのは、決まった値を台帳に載せ、
台帳の外に値が増えていないかを見張ること。

## 役割分界（重複させない）

| このスキルがやること | やらないこと（担当スキル） |
|---|---|
| トークン台帳の所有（追加・改名・廃止） | コントラストの検算（`a11y-contrast-guard`） |
| 定義の真実の源（どのファイルが正か）の固定 | **採用色の最終決定（DESIGN の領域）** |
| 命名の衝突確認 | 画面仕様の起草（`ux-screen-spec-writer`） |
| 逸脱一覧の記録と期限の管理 | 例外を恒久化する判断（`ux-decision-record`） |
| — | UI 全体の評価（`ux-design-review`） |

## 最初に読む

| ファイル | 何のために |
|---|---|
| `pd/specs/05-surface/design-tokens.md` | 既存のトークンと逸脱一覧 |
| `skills/analyze/uiux/rules/04-accessibility.md` | 下限と、検算のやり方 |

## 手順

### 1. 真実の源を先に固定する

台帳の冒頭に、**どのファイルが定義の正か**を書く。

```
真実の源: <定義ファイルのパス>
```

プロジェクトごとに違うため plugin 側には書けない。**ここが空の台帳は台帳ではない。**
同じトークンが2箇所で定義されている状態を見つけたら、どちらが正かを決めるまで追加を止める。

### 2. 既存で足りるかを先に見る

新しい値を足す前に、**既存トークンで受けられないか**を必ず確認する。
「少しだけ違う色」を足し続けると、テーマ変更が破綻する。

| 判断 | 条件 |
|---|---|
| 既存を使う | 意味も見た目も既存と同じ役割 |
| 既存を広げる | 役割は同じで、値の見直しが妥当（**既存の利用箇所すべてが影響を受ける**） |
| 新規に足す | 既存に無い**役割**がある（見た目の微差ではなく役割の差） |

### 3. 命名を決める（衝突を先に確認する）

- 役割で名付ける（`色そのもの`ではなく`どこに使うか`）
- **標準のユーティリティクラス名との衝突を先に確認する。**
  トークン名がそのままクラス名になるフレームワークでは、標準側を黙って上書きする。
  ビルドは通るため気付けない（`base` `sm` `lg` `xl` `full` `none` などが衝突しやすい）

### 4. 下限を満たしているか確かめる

色を足す・変えるときは `a11y-contrast-guard` を先に通す。
**検算は実ビルド出力の hex で行う。** 近似値で合否を判定しない。
取れなかった場合は「実測できていない」と書く。

### 5. 台帳に載せる

`skills/analyze/uiux/templates/design-tokens.md` を Schema として
`pd/specs/05-surface/design-tokens.md` に**上書き**する（現在値）。

| トークン名 | 値 | 役割（どこに使うか） | 対の背景 | コントラスト | 決定者 |
|---|---|---|---|---|---|

### 6. 逸脱を記録する（**期限つきで**）

基準を割っている実測箇所、トークン外の直書き、廃止したはずのトークンの残存は
**逸脱一覧**に追記する。

| 箇所 | 何が逸脱しているか | 実測値 | 下限 | 期限 | 担当 |
|---|---|---|---|---|---|

> ⚠️ **期限の無い例外は恒久化する。**
> 期限を決められない場合は「未定」ではなく、`ux-decision-record` へ回して
> **棄却条件つきの作業仮説**として記録する。

### 7. 廃止するときは、残っていないことを確認してから

トークンを消す前に、使われていないことを確認する。
確認範囲を必ず添える（範囲を書けないなら、それは調べていない）。

## 出力形式

```
■ 真実の源: <定義ファイルのパス / 未固定（ここで停止）>
■ 操作: 追加 / 変更 / 廃止（トークン名: <…>）
■ 判断: 既存を使う / 既存を広げる（影響: <箇所数>）/ 新規（役割の差: <…>）
■ 命名の衝突確認: 済（範囲: <…>）/ 未
■ コントラスト: <実測値>（下限 <値>）/ 実測できていない
■ 逸脱: <件数>（期限が未定のもの: <件数> ← UXDR へ）
■ 記録先: pd/specs/05-surface/design-tokens.md
■ 値の最終決定: DESIGN（このスキルは決めない）
```

## 禁止

- 真実の源が固定されていない状態でトークンを足す
- 見た目の微差で新規トークンを足す（役割の差でのみ足す）
- 命名の衝突を確認せずに足す
- 期限の無い逸脱を一覧に残す
- 近似値でコントラストの合否を判定する
- このスキルが採用色を決める（下限までが UX の領域。決めるのは DESIGN）
