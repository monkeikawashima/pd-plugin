# object-model-reviewer — 構造層の点検とオブジェクト定義

## 役割分界（重複させない）

| このスキルがやること | やらないこと（担当スキル） |
|---|---|
| 既存オブジェクトへの収まりの点検 | 層の判定（`ux-layer-triage`） |
| 新規オブジェクトの定義 | ストーリーの書式化（`user-story-writer`） |
| フェーズ別コア／サブの更新 | 画面の評価（`ux-design-review`） |
| `taxonomy.json` の語彙更新 | 決定の記録（`ux-decision-record`） |
| — | 画面仕様の起草（`ux-screen-spec-writer`） |

## 最初に読む

| ファイル | 何のために |
|---|---|
| `pd/specs/03-structure/object-model.md` | 既存の対象物と関係、ハブ |
| `pd/specs/03-structure/core-objects.md` | フェーズ別のコア／サブ |
| `pd/specs/02-requirements/user-stories.md` | どのストーリーが関わるか |

> ⚠️ **オブジェクト名を記憶で答えない。** 必ず spec と実スキーマを見る。

---

## パートA｜点検（既存オブジェクトで受けられるか）

### 1. どのフェーズの話かを決める

`core-objects.md` から。フェーズが未定義なら「**フェーズ未定義**」と明記し、
`00-common-language.md` の作業仮説の形で仮のフェーズを置く（棄却条件つき）。

### 2. そのフェーズのコアへ最短で導けているか確認する

> **この関心は、いまのフェーズのコアに近づけているか。遠ざけていないか。**

### 3. 既存オブジェクトで受けられるか確認する

| 判定 | 次 |
|---|---|
| 受けられる | 既存オブジェクトの属性・関係の追加として扱う → 骨格層へ |
| 受けられない | パートBへ |

---

## パートB｜新規オブジェクトを立てる

### 1. 関心を一人称の疑問文で言語化する

```
✕ 分析ダッシュボード
◯「自分は今日どうだったか」
```

**疑問文にできない関心は、まだ関心ではない**（機能名のまま）。

### 2. ハブから外れないかを確認する（重要）

`object-model.md` のハブに紐づくか。

> **ハブに紐づかない関心は、現行構造の外側にある＝新しい設計が必要。**
> ここを飛ばすと、既存構造に無理やり接ぎ木した歪んだ実装になる。

### 3. データ構造上の実体を確認する（**開発チーム同席が必須**）

実テーブル・型・RLS を確認する。**確認できない項目は Q の形で並べて停止する**（下記の出力形式）。

### 4. フェーズごとのコア／サブを決める

| フェーズ | コア | サブ | 境界（次へ渡すもの） |
|---|---|---|---|

### 5. 操作をユーザーストーリーに展開する

`user-story-writer` へ渡す。

### 6. 棄却条件を書く

> このオブジェクト定義は、<何が観測されたら> 捨てる。

### 7. 台帳の語彙を更新する

構造層が確定したら `pd/voices/taxonomy.json` の `object` / `phase` を埋める。
利用者の役割が固まっていれば `speaker_role` も埋める（**plugin 側に既定値は無い**）。
（空配列のままなら自由記述が許可される。埋めた瞬間から `validate` が値を検査する）

## 出力形式

```
■ パート: A（点検） / B（新規定義）
■ フェーズ: <名前 / 未定義（作業仮説: … / 棄却条件: …）>
■ 関心（一人称の疑問文）: 「…」
■ コアへの距離: 近づける / 遠ざける / 影響なし
■ 既存オブジェクトで受けられるか: 受けられる（<名前>） / 受けられない
■ 新規オブジェクト案: <名前>
   ハブとの関係: <紐づく / 紐づかない（＝現行構造の外側）>
   データ構造上の実体: <テーブル / 未確認>
   フェーズ別: コア=… サブ=…
   棄却条件: …

■ 開発チームへの確認事項（ここで停止する）
   Q1. …
   Q2. …

■ 次のアクション: <スキル名 / 人間の確認待ち>
```

## 禁止

- **開発チーム不在で構造層を「合意済み」にする**
- スキーマ都合だけでオブジェクトを増やす
- 「画面が欲しい」をそのままオブジェクトにする
- ハブとの関係を確認せずに新規オブジェクトを立てる
- 実スキーマを見ずに「このテーブルに対応する」と書く
