# ux-layer-triage — 受付と層判定

**UI/UX 作業の入口。ここを通さない要望に着手しない。**

## 役割分界（重複させない）

| このスキルがやること | やらないこと（担当スキル） |
|---|---|
| 要望の受付と「関心」への翻訳 | 生の声の保存（`user-voice-ledger`） |
| 5層のどれかの判定 | ストーリー化（`user-story-writer`） |
| 上流の欠落の特定と作業仮説の提示 | オブジェクトを立てる判断（`object-model-reviewer`） |
| 次スキルへの振り分け | UI の良し悪しの評価（`ux-design-review`） |
| — | 戦略の言語化（`strategy-insight-writer`） |
| — | 利用者像の集計（`user-persona-builder`） |
| — | 決定の記録（`ux-decision-record`） |

## 最初に読む

| ファイル | 何のために |
|---|---|
| `skills/analyze/uiux/rules/00-common-language.md` | 5層の定義 |
| `pd/specs/00-status.md` | どの層まで成果物があるか |
| `pd/specs/01-strategy/concept.md` | 還元テストの対象 |

## 手順

### 0. 顧客の声なら、先に台帳へ

「ユーザーがこう言っていた」「クレームが来た」「レビューに書かれていた」など**生の発言**が含まれる場合、
判定より先に `user-voice-ledger` を呼ぶ。**要約すると一次情報が失われる。**

### 1. 機能名を一度捨てる

「◯◯が欲しい」を「**誰の、どんな関心が置き場所を失っているか**」に翻訳する。

```
✕「ダッシュボードが欲しい」
◯「利用者が『自分は今日どうだったか』を確認する場所が無い」
```

### 2. 層を判定する（上から当て、最初に YES になった層を採用）

| 順 | 質問 | YES なら |
|---|---|---|
| 1 | 誰のために作るか・何を成功と呼ぶかの話か | **戦略** |
| 2 | 何を提供するか（体験の単位）の話か | **要件** |
| 3 | 何を対象物として扱い、どう関係づけるかの話か | **構造** |
| 4 | 画面のどこに何を置き、どう操作するかの話か | **骨格** |
| 5 | 見た目（色・タイポ・余白）の話か | **表層** |

**よくある誤判定**

| 見た目の話に見えて | 実は | 見分け方 |
|---|---|---|
| 「目立たないから色を変えたい」 | **要件**（なぜ押させたいのかが未定義） | 「なぜ目立たせたいか」に答えられるか |
| 「情報が多すぎる」 | **構造**（コアが決まっていない） | そのフェーズの主役が特定できているか |
| 「一覧に項目を足したい」 | **構造** → 骨格 | 対象物の定義に属するか |
| 「競合にあるから欲しい」 | **戦略**（ポジショニング） | A/B/C のどれか |

### 3. 上流の欠落をチェックする

| 判定した層 | 必要な上流 | 欠けていたら |
|---|---|---|
| 戦略 | 一次情報（`pd/voices/`） | `user-voice-ledger` で先に台帳へ |
| 要件 | `pd/specs/01-strategy/`（コンセプト・ペルソナ） | `strategy-insight-writer` / `user-persona-builder` |
| 構造 | `pd/specs/02-requirements/`（ストーリー・ジャーニー） | `user-story-writer` / `ux-journey-mapper` |
| 骨格 | `pd/specs/03-structure/` | `object-model-reviewer` |
| 表層 | `pd/specs/04-skeleton/` | `ux-screen-spec-writer` |

上流が未定義でも「判断できません」で終わらせない。**作業仮説の形で出す**（下記の出力形式）。

### 4. コンセプト還元テスト

`pd/specs/01-strategy/concept.md` の要素のどれに効くかを一文で書く。

- 書けない → **却下ではなく「まだ要件ではない」**
- 書けないが価値がありそう → **「コンセプトの反証候補」**として記録する
- コンセプト自体が未定義 → 「**還元テスト実施不能（上流が空）**」と明記する（省略しない）

### 5. 振り分ける

| 層 | 状況 | 次のスキル |
|---|---|---|
| 戦略 | 誰のため・何を成功と呼ぶかが未定義 | `strategy-insight-writer` |
| 戦略 | 利用者像を揃える | `user-persona-builder` |
| 要件 | 要件として言語化する | `user-story-writer` |
| 要件 | 画面をまたぐ流れ・詰まりの話 | `ux-journey-mapper` |
| 構造 | 対象物への収まりが怪しい | `object-model-reviewer` |
| 骨格 | **これから作る**画面の設計 | `ux-screen-spec-writer` |
| 骨格 | **既に在る** UI の評価 | `ux-design-review` |
| 表層 | 色・コントラストの下限 | `a11y-contrast-guard` |
| 表層 | トークンの追加・整理・逸脱 | `design-token-keeper` |
| 横断 | 一意に決まらない | `ux-validation-planner` |
| 横断 | 数値の話 | `ux-measurement` |
| 横断 | 上流が変わった | `ux-update-cascade` |

> ⚠️ **骨格層で `ux-design-review` に流すのは、対象が既に実装されている場合だけ。**
> これから作るものをレビューのスキルに渡すと、作り直しの指摘しか出せなくなる。

### 6. 記録する

採用 / 保留 / 不採用とその理由を `ux-decision-record` へ。

## 出力形式

```
■ 層: <戦略 / 要件 / 構造 / 骨格 / 表層>
■ 根拠: <なぜこの層か。判定に使った質問番号>
■ 翻訳した関心: <誰の、どんな関心が置き場所を失っているか>
■ 上流の状態: 有り / 無し
   （無い場合）欠けているもの: <spec 名>
   先に決めるべきは: <何を決めればこの判断が根拠を持つか>
   作業仮説: <仮に置く仮定>
   棄却条件: <何が観測されたらこの仮定を捨てるか>
■ コンセプト還元: <どの要素に効くか一文 / 実施不能（上流が空）>
■ 関連ボイス: VOICE-xxx / 一次情報なし
■ 次のアクション: <スキル名>
```

## 禁止

- 層を決めずに中身の議論に入る
- 上流が無いことを理由に「判断できません」で止める（作業仮説を出す）
- 棄却条件のない仮置き
- 生の声を要約してから台帳に渡す
- 「競合にあるから」を差別化の根拠として通す（それは分類 A ＝相場の話）
