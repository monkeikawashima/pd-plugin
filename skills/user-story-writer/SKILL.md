# user-story-writer — 要件層の言語化

## 役割分界（重複させない）

| このスキルがやること | やらないこと（担当スキル） |
|---|---|
| ストーリーの起草・採番 | 層の判定と受付（`ux-layer-triage`） |
| 体験の原則への紐づけ | 新規オブジェクトを立てる判断（`object-model-reviewer`） |
| 既存ストーリーとの重複・矛盾の突合 | 生の声の保存（`user-voice-ledger`） |
| 実装状況の判定と判定根拠の明示 | 決定の記録（`ux-decision-record`） |

**前提**: 層の判定は `ux-layer-triage` が済ませている。

## 最初に読む

| ファイル | 何のために |
|---|---|
| `pd/specs/02-requirements/user-stories.md` | 既存ストーリーとの突合 |
| `pd/specs/02-requirements/experience-principles.md` | 紐づける原則 |
| `pd/specs/03-structure/object-model.md` | 対象に使えるオブジェクト名 |
| `skills/pd/uiux/templates/user-story.md` | 個票の書式 |

## 書式（厳守）

```
〈アクター〉は、〈対象〉を〈できる〉。なぜなら〈目的〉したいから
```

## 手順

### 1. アクターを決める

役割名で書く。**「ユーザー」で済ませない**（誰のことか特定できない要件は検証できない）。
役割の呼称は `skills/pd/uiux/glossary.md` に従う。

### 2. 対象をオブジェクト名にする

`pd/specs/03-structure/object-model.md` の定義から取る。

- 定義に無い → 「**新規候補**」と書き、`object-model-reviewer` へ回す
- **画面名・機能名を対象にしない**（「◯◯管理画面を使える」は要件ではない）

### 3.「できる」に操作を書く

機能名ではなく**操作**。

```
✕ 通知機能を使える
◯ 担当している対象物に動きがあったことを知ることができる
```

### 4.「なぜなら」に目的を書く

**手段の言い換えを目的と呼ばない。**

```
✕ なぜなら通知を受け取りたいから（＝手段の言い換え）
◯ なぜなら受けるかどうかをその場で判断したいから
```

### 5. 体験の原則に紐づける

`experience-principles.md` の番号を書く。

- **どの原則にも紐づかないものは要件に入れない**
- 原則自体が未定義なら「**原則未定義のため紐づけ不能**」と明記する（空欄にしない）

### 6. 根拠ボイスを紐づける

```bash
pnpm voices query --screen <画面名>
```

| 状況 | 書き方 |
|---|---|
| ヒットあり | `VOICE-xxx` |
| 0件 | **「デザイナー起案」**（「顧客要望」と書かない） |

### 7. 既存と突合する

重複・矛盾を確認する。重複するなら既存に統合し、矛盾するなら**両方を並べて UXDR へ**（勝手に片方を消さない）。

### 8. 実装状況を判定する

| 判定 | 意味 |
|---|---|
| `実装済み` | 機能が存在する（**品質が要求を満たすかは別問題**） |
| `部分実装` | 一部の条件でのみ成立する |
| `不足` | 存在しない |

**判定根拠を必ず添える**: `実機画面` / `コード（パス）` / `未確認`。
**未確認のまま `実装済み` と書かない。**

## 出力形式

```
■ US-<ID>: 〈アクター〉は、〈対象〉を〈できる〉。なぜなら〈目的〉したいから
   対象オブジェクト: <名前 / 新規候補>
   効く原則: <番号 / 原則未定義のため紐づけ不能>
   コンセプト還元: <一文 / 実施不能（上流が空）>
   根拠ボイス: VOICE-xxx / デザイナー起案
   実装状況: <実装済み / 部分実装 / 不足>（判定根拠: <実機画面 / コード: path / 未確認>）
   既存との関係: 新規 / US-yy と重複 / US-zz と矛盾

■ 要件に入れられなかったもの: <理由つき>
■ 次のアクション: <スキル名>
```

## アンチパターン

| ✕ | なぜだめか |
|---|---|
| 機能名がそのまま対象になっている | 対象物ではなく実装の話。構造層を飛ばしている |
| 目的が手段の言い換え | なぜやるかが決まっていない＝優先度が付けられない |
| どの原則にも紐づかない | 判断軸の外にある＝要件ではない |
| 根拠ボイスが無いのに「顧客要望」 | 一次情報の捏造 |
| 未確認で「実装済み」 | 棚卸しの結果が信用できなくなる |
