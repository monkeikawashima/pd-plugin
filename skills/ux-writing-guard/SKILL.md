# ux-writing-guard — 文言の点検

**文言は表層ではなく、多くの場合は要件と構造の露出。**
「何と呼ぶか」が決まっていないものは、まだ設計されていない。

## 役割分界（重複させない）

| このスキルがやること | やらないこと（担当スキル） |
|---|---|
| 呼称の一致（用語集との突合） | 呼称そのものを決める（`pd/specs/01-strategy/glossary.md` / BIZ） |
| 文言の型の点検（エラー・空状態・ラベル） | 画面仕様の起草（`ux-screen-spec-writer`） |
| 「まだ名前が無いもの」の検出 | 層の判定（`ux-layer-triage`） |
| — | UI 全体の評価（`ux-design-review`） |
| — | 決定の記録（`ux-decision-record`） |

## 最初に読む

| ファイル | 何のために |
|---|---|
| `pd/specs/01-strategy/glossary.md` | 使ってよい呼称・業務用語 |
| `pd/specs/03-structure/object-model.md` | 対象物の名前 |
| `pd/specs/04-skeleton/screens/` | 対象画面の仕様 |

## 点検項目

### 1. 呼称（**最優先**）

| 見るところ | 下限 |
|---|---|
| 利用者の呼び方 | 用語集で決めた呼称。**「ユーザー」を単独で使わない** |
| 対象物の呼び方 | `object-model.md` にある名前。UI だけの別名を作らない |
| 同じものが2つの名前で出ていないか | 画面と通知とメールで表記を揃える |

> ⚠️ **UI に出す語が用語集に無いなら、それは文言の問題ではない。**
> 名前が無いものが画面に出ている＝**構造層が未決着**。`object-model-reviewer` へ戻す。

### 2. エラー

**エラー文の役割は、謝ることでも、原因を説明することでもなく、次の行動を示すこと。**

| 型 | 中身 |
|---|---|
| 何が起きたか | 利用者の言葉で（内部用語・コード番号だけにしない） |
| なぜ | 分かる場合のみ。分からないなら書かない（推測を断定にしない） |
| **次に何をすればよいか** | **必須。ここが無いエラー文は、ただの通知** |
| 誰でも直せないとき | 誰に言えばよいか（問い合わせ先・担当） |

### 3. 空状態（**空振りの文言**）

| 状況 | 書くこと |
|---|---|
| まだ何も無い（初回） | 何を置く場所か・最初の一歩 |
| **条件に合うものが無い**（0件） | 条件を変える手段。**「該当なし」だけで終わらせない** |
| 権限が無くて見えない | 見えない理由と、誰に言えばよいか |

> **「0件」と「エラー」と「まだ作っていない」を同じ文言にしない。** 利用者の次の行動が違う。

### 4. 操作のラベル

| 見るところ | 下限 |
|---|---|
| ボタン | **押した結果**を書く（「はい / いいえ」「OK」だけにしない） |
| 取り消せない操作 | 何が失われるかを、確認の文面に書く |
| 進行中 | 何が起きているか（「処理中」だけにしない） |

### 5. 曖昧語

| 避ける | なぜ |
|---|---|
| 「しばらく」「まもなく」 | 待てる時間か判断できない |
| 「エラーが発生しました」だけ | 次の行動が無い |
| 「正常に完了しました」だけ | 何が起きたか分からない |
| 内部用語・略語 | 作った側にしか読めない |

## 手順

1. **対象の文言を全部並べる**（画面・通知・メール・空状態・エラーを漏らさない）
2. 用語集と突き合わせる。**用語集に無い語を見つけたら、そこで止めて構造層へ返す**
3. 上の型に当てて、欠けているものを挙げる
4. 直せるもの（誰が見ても同じ結論になる）と、決まらないもの（呼称そのものの選択）を分ける
5. 決まらないものは `ux-decision-record` へ。呼称を変える判断は**用語集の更新**であり、`ux-update-cascade` の対象

## 出力形式

```
■ 対象: <画面 / 機能>
■ 用語集との不一致: <n> 件（<語> → <正しい呼称>）
■ 用語集に無い語: <n> 件 ← **構造層へ戻す候補**
■ エラー: 次の行動が無いもの <n> 件
■ 空状態: 0件・初回・権限の書き分けができていないもの <n> 件
■ ラベル: 結果が読み取れないもの <n> 件
■ 直せるもの / 決まらないもの: <n> / <n>
■ 記録先: pd/reviews/{プロダクト}/{年}/DR-… （レビュー結果として）
```

## 禁止

- 用語集にない呼称を、このスキルが決める
- 「ユーザー」を単独で使う（どの系統かを必ず指定する）
- 次の行動が無いエラー文を通す
- 0件・初回・権限なしを同じ文言で済ませる
- 原因が分からないのに、それらしい原因を書く
