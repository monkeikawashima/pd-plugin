# 04 — アクセシビリティ（表層の下限）

表層で**議論の余地がない下限**を固定する。ここは好みの領域ではない。

---

## 1. コントラスト基準値（WCAG 2.1 AA）

| 対象 | 基準 |
|---|---|
| 通常テキスト | **4.5:1** |
| 大きいテキスト（18pt 以上 / 14pt 太字以上） | **3:1** |
| 非文字要素（境界線・アイコン・入力枠・フォーカスリング） | **3:1** |
| **プレースホルダー** | **4.5:1**（通常テキスト扱い） |

> プレースホルダーを 3:1 で許容しない。**入力前は唯一の手がかり**であり、装飾ではない。

計算式（相対輝度 L から）:

```
contrast = (L_lighter + 0.05) / (L_darker + 0.05)
```

---

## 2. 役割分担 — 下限は UX、決定は DESIGN

| やること | 誰 |
|---|---|
| 基準を満たすかの検算 | UX（`a11y-contrast-guard`） |
| 満たさない場合の**下限値の算出**（「ここまでは必要」の証明） | UX |
| **どの色を採用するか** | **DESIGN** |

UX は「この色ではダメ」と「最低ここまで」までを示す。**採用色を指定しない。**

---

## 3. 修正するときは色相を変えず、輝度だけ動かす

基準を割ったときの直し方:

1. 色相（hue）と彩度（chroma）を保つ
2. **明度だけ**を動かして基準を満たす最小の値を求める
3. その値を「下限」として提示する

色相ごと変えるとブランドの印象が変わる。それは a11y の判断ではなくデザインの判断。

---

## 4. 状態を色だけで区別しない

成功・警告・エラー・無効・選択中を**色の違いだけ**で表現しない。
色覚特性・低コントラスト環境・モノクロ印刷で情報が消える。

必ず次のいずれかを併用する:

- 文字（ラベル・ステータス名）
- 形・アイコン
- 位置・罫線・塗りの有無

---

## 5. その他の下限

| 項目 | 下限 |
|---|---|
| タップターゲット | 44 × 44 px（モバイル） |
| フォーカスリング | 消してよいのは、同等の `:focus-visible` 演出を置いた場合のみ |
| アイコンのみのボタン | `aria-label` 必須 |
| フォーム | `<label>` と `id` を対で |

---

## 6. 検算は「実ビルド出力の hex」で行う

`oklch()` などの色空間関数はビルド時に sRGB の hex へ変換される。
**手計算の近似は基準の境界付近で合否が変わる。**

```bash
pnpm build
grep -oE '\-\-<変数名>:[^;]*' $(find .next -name '*.css' | grep static)
```

出てきた hex で検算する。hex 直接指定のトークンではこの問題は起きない。

---

## 7. トークン名が標準ユーティリティを奪う事故に注意

Tailwind v4 の `@theme` で `--color-<name>` を定義すると `text-<name>` / `bg-<name>` が生成され、
**同名の標準ユーティリティを黙って上書きする**（`base` `sm` `lg` `xl` `full` `none` など）。
ビルドは通るので気付けない。新しいカラートークンを足すときは、標準ユーティリティ名との衝突を先に確認する。
