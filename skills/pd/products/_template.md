# プロダクトコンテキスト

新しいプロダクトを追加する場合は、このファイルを `products/{product-name}.md` へ複製して記述する。
`framework/` は変更しない。

存在しない情報を推測で埋めない。不明な項目は `未確認` / `不明` / `情報不足` と記載し、空欄のまま残さない。

## 基本情報

### プロダクト名

プロダクト名を記載する。

### プロダクト概要

何を提供するプロダクトなのかを簡潔に記載する。

### プロダクトの目的

このプロダクトが存在する目的を記載する。


## ユーザー

### Primary User

主要ユーザーを記載する。

### Secondary User

必要な場合のみ記載する。

### 利用シーン

どのような状況で利用されるかを記載する。

### Jobs / Use Cases

ユーザーが達成したいことを記載する。


## Goal

### Business Goal

事業として達成したい成果。

### User Goal

ユーザーが達成したい成果。

> Business Goal と User Goal は分けて記載する。両者が衝突している場合、その衝突自体が分析上の発見になる。


## KPI

### Primary KPI

最重要 KPI。

### Secondary KPI

補助的な KPI。

### Leading Indicator

最終 KPI より先に変化する指標。

> 各指標について、現在の値が計測されているかどうかも記載する。未計測なら「未取得」と明記する。

### 必須 Segment

分析のたびに切り口を場当たりに決めないため、**このプロダクトで必ず見る Segment** を固定する。1行で書く。

```
必須 Segment: 新規/既存 ・ 利用頻度 ・ 導入からの経過月数
```

意味のある軸だけを置く。分解できない軸を並べない。


## User Journey

### 主要なユーザーフロー

ユーザーが目的を達成する主要フロー。


## Workflow

### 現在の業務フロー

必要な場合、プロダクト利用前後を含めて記載する。


## Current State

### 現在の状況

現在確認されている状態。数値がある場合は出典とともに記載する。

### Expected State

期待する状態。

### Gap

Current State と Expected State の差。


## Known Issues

### 確認されている問題

Evidence がある課題を記載する。Evidence の無い懸念はここに書かず、Unknowns へ回す。


## Constraints

### Business

ビジネス上の制約。

### Operation

運用上の制約。

### Technical

技術上の制約。

### Organization

組織上の制約。


## Available Evidence

### Quantitative

利用可能な定量データ。

### Qualitative

利用可能な定性データ。Voice は `voices/{product-name}/` にある（逐語の全文はそこが正。**ここにファイル名を列挙しない** — 追加のたびに乖離する）。

ここに書くのは、Voice 全体から見えている状態。

| 項目 | 内容 |
|---|---|
| 取得済みの範囲 | どの立場・どの経路の声が、いつの時点まで取れているか |
| 得られている論点 | 繰り返し現れている論点。飽和しているかどうか |
| 欠けている声 | 取れていない立場（非利用者 / 離脱者 / 解約者 / 沈黙している多数 など） |

Voice が1件も無い場合は `情報不足` と書き、「あり」としない。

### Behavioral

利用可能な行動データ。

> 「取得できるはずのデータ」ではなく「実際に到達できるデータ」を書く。


## Past Experiments

### 実施済みの検証

これまで行った Experiment。出典として `analyses/{product-name}/` の該当 Note を挙げる。

### 結果

確認された結果。**棄却された仮説も残す。** 棄却された仮説には、何によって棄却されたかを併記する。同じ仮説を再度持ち出さないため。

**予測と実測を対で残す。** 見立てがどれだけ当たるかを測るため。

| 仮説 | Confidence | 予測 | 実測 | 差分 | 結果 |
|---|---|---|---|---|---|
| H1 | Medium | 完了率 40〜45% | 37% | −3pt | 棄却 |

数回積むと、`High` / `Medium` / `Low` の実際の的中率が分かる。以後は Confidence の重みを実測に合わせる。実測が無い段は空欄でよい（**埋めるための埋めをしない**）。


## Decisions

### 決定事項

すでに決定している事項。次を併記する。

| 項目 | 内容 |
|---|---|
| 決定 | 何を決めたか |
| 決定日 | いつ |
| 根拠 | 出典（`analyses/` の Note 名）と Evidence の状態 |
| 見直し条件 | どうなったら見直すか |
| 確認者・時期 | 誰がいつ確認するか |

### 保留中の見直し

見直し条件が未確認のまま残っている決定を挙げる。確認されたら決定事項側を更新し、ここから外す。確認者と時期が無い項目は、実行されないものとして扱う。


## Unknowns

### 現時点で不足している情報

分析や意思決定に必要だが未確認の情報。
