# 00 — 共通言語（5段階モデル）

UI/UX の議論を「好み」で終わらせないための座標系。**発言の中身に入る前に、まずどの層の話かを決める。**

---

## 1. 5層の定義

| 層 | 答える問い | 中間成果物 | 担当スキル |
|---|---|---|---|
| **戦略** | 誰のために作るか。何を成功と呼ぶか | インサイト / コンセプト / KPI / ポジショニング / **ペルソナ** | `ux-research-planner` / `strategy-insight-writer` / `user-persona-builder` |
| **要件** | 何を提供するか（体験の単位） | 体験の原則 / ユーザーストーリー / **ジャーニー** | `user-story-writer` / `ux-journey-mapper` |
| **構造** | 何を対象物として扱い、どう関係づけるか | オブジェクトモデル / フェーズ別コアオブジェクト | `object-model-reviewer` |
| **骨格** | 画面のどこに何を置き、どう操作するか | レイアウト仮説 / 画面仕様 / **ナビゲーション** / 文言 | `ia-navigation-reviewer` / `ux-screen-spec-writer` / `ux-writing-guard` / `a11y-interaction-guard` |
| **表層** | どう見えるか（色・タイポ・余白） | デザイントークン / 逸脱一覧 | `design-token-keeper` / `a11y-contrast-guard` |

出典: Jesse James Garrett『The Elements of User Experience』の Strategy / Scope / Structure / Skeleton / Surface。

---

## 1.5 5層が持たない軸 — 時間

**5層は静的な断面であり、順序や所要時間を表さない。**
「どの画面が悪いか」では説明できない詰まり（画面はどれも問題ないのに全体が遅い、
別々の画面を往復している）は、層だけを見ていると永久に見つからない。

時間軸は**ジャーニー**が受け持つ（要件層に属し、`ux-journey-mapper` が所有する）。

> ⚠️ **ジャーニーのステップは、主要タスク時間の構成要素と同一物として扱う。**
> 別々に管理すると必ず食い違い、どちらが正か誰にも分からなくなる。

---

## 2. 会話での使い方

議論が噛み合わなくなったら、誰が誰に対して言ってよい一言:

> **「それは、どの層の話ですか？」**

具体例:

| 発言 | 実際の層 | なぜ |
|---|---|---|
| 「このボタン、目立たないから赤くしたい」 | **表層**。ただし「なぜ目立たせたいか」を辿ると**要件**の可能性がある | 押させたい理由が要件層に無ければ、色は好みの議論になる |
| 「一覧に◯◯も出したい」 | **構造**（何を対象物として扱うか）→ その後 **骨格** | 表示項目の追加は、まず対象物の定義に属する |
| 「使いにくいと言われた」 | **未判定**。まず一次情報として台帳へ | 逐語を失うと層の判定材料が消える |

---

## 3. 禁止事項

> **上の層の成果物が無いまま、下の層を触らない。**

これは「上流が固まるまで下流を止める」という意味では**ない**。止めると何も進まない。

上流が未定義のまま下流を進める場合は、**作業仮説として明示する**:

```
これは【骨格】の話です。
ただし上流の【要件】が未定義のため、いま決めると根拠が「好み」になります。
先に決めるべきは: <何を決めればこの判断が根拠を持つか>
仮に進める場合の作業仮説: <置く仮定>
棄却条件: <何が観測されたらこの仮定を捨てるか>
```

**棄却条件のない仮置きは、作業仮説ではなく単なる思い込み。**

---

## 4. 層をまたぐときのルール

- 連鎖は**一方向（上→下）**。上流が変われば下流は再検証の対象になる（`ux-update-cascade`）
- フィードバックは**双方向**。検証で下流から上流の前提が崩れることがある（`ux-validation-planner`）
- spec は「その時点の合意を固定して下流を進めるためのもの」。**更新しないという意味ではない**
