# 04 — アクセシビリティ（表層の下限）

表層で**議論の余地がない下限**を固定する。ここは好みの領域ではない。

---

## 1. コントラスト基準値（WCAG 2.1 AA）

| 対象 | 基準 |
|---|---|
| 通常テキスト | **4.5:1** |
| 大きいテキスト（18pt 以上 / 14pt 太字以上） | **3:1** |
| 非文字要素（境界線・アイコン・入力枠・フォーカスリング） | **3:1** |
| **プレースホルダー** | **4.5:1**（通常テキスト扱い） |

> プレースホルダーを 3:1 で許容しない。**入力前は唯一の手がかり**であり、装飾ではない。

計算式（相対輝度 L から）:

```
contrast = (L_lighter + 0.05) / (L_darker + 0.05)
```

---

## 2. 役割分担 — 下限は UX、決定は DESIGN

| やること | 誰 |
|---|---|
| 基準を満たすかの検算 | UX（`a11y-contrast-guard`） |
| 満たさない場合の**下限値の算出**（「ここまでは必要」の証明） | UX |
| **どの色を採用するか** | **DESIGN** |

UX は「この色ではダメ」と「最低ここまで」までを示す。**採用色を指定しない。**

---

## 3. 修正するときは色相を変えず、輝度だけ動かす

基準を割ったときの直し方:

1. 色相（hue）と彩度（chroma）を保つ
2. **明度だけ**を動かして基準を満たす最小の値を求める
3. その値を「下限」として提示する

色相ごと変えるとブランドの印象が変わる。それは a11y の判断ではなくデザインの判断。

---

## 4. 状態を色だけで区別しない

成功・警告・エラー・無効・選択中を**色の違いだけ**で表現しない。
色覚特性・低コントラスト環境・モノクロ印刷で情報が消える。

必ず次のいずれかを併用する:

- 文字（ラベル・ステータス名）
- 形・アイコン
- 位置・罫線・塗りの有無

---

## 5. 色以外の下限

**色は値の計算で判定できるが、操作は実際に動かさないと判定できない。**
検査は `a11y-interaction-guard` が受け持つ。ここには下限だけを置く。

### 5.1 キーボード

| 項目 | 下限 |
|---|---|
| 到達 | すべての操作要素へ Tab / Shift+Tab で到達できる |
| 実行 | Enter / Space で実行、Esc で閉じる |
| **罠** | 入ったら出られない領域を作らない（モーダル・エディタ・埋め込み） |
| 独自のクリック領域 | クリック処理だけを付けた非操作要素は到達できない。役割と操作を持たせる |
| ホバー | **ホバーでしか出ない情報・操作を作らない。** フォーカスでも同じものを出す |

### 5.2 フォーカス

| 項目 | 下限 |
|---|---|
| 順序 | 画面の読み順と一致する（見た目の並べ替えで壊れていないか） |
| 可視性 | 常に見える（非文字要素として **3:1**） |
| リング | 消してよいのは、同等の `:focus-visible` 演出を置いた場合のみ |
| 開いたとき | モーダル・ドロワーの中へ移す |
| 閉じたとき | **開く操作をした要素へ戻す**（先頭へ飛ばさない） |
| 消えたとき | フォーカス中の要素を消す前に、行き先を決める |

### 5.3 読み上げ

| 項目 | 下限 |
|---|---|
| アイコンのみのボタン | 名前を持つ（`aria-label` 等） |
| フォーム | `<label>` と `id` を対で。**プレースホルダーはラベルの代わりにならない** |
| 画像 | 意味のある画像には説明、装飾なら空にする |
| 状態 | 開閉・選択・並び順・エラーが、見た目以外でも伝わる |
| **非同期の変化** | 読み込み完了・**0件**・保存成功が、黙って画面だけ変わらない |
| 見出し | 階層を飛ばさない（見た目の大きさで選ばない） |

> ⚠️ **「空振り」は読み上げでも空振りになりやすい。**
> 0件・該当なしを画面に出すだけで通知が無いと、利用者は待ち続ける。

### 5.4 寸法

| 項目 | 下限 |
|---|---|
| タップターゲット | 44 × 44 px（モバイル） |
| 隣接する操作要素 | 誤タップが起きない間隔 |
| 文字の拡大 | 200% で内容と操作が失われない |

### 5.5 動き

| 項目 | 下限 |
|---|---|
| 大きな動き（視差・回転・拡大・自動スクロール） | 抑制設定を有効にしている利用者には出さない |
| 自動再生・自動切り替え | 止める手段を用意する |
| 点滅 | 1秒に3回を超えない |

> **確かめられなかった項目は「未確認」と書く。**「たぶん大丈夫」を通さない。

---

## 6. 検算は「実ビルド出力の hex」で行う

`oklch()` などの色空間関数はビルド時に sRGB の hex へ変換される。
**手計算の近似は基準の境界付近で合否が変わる。**

**ソースの値ではなく、ビルド成果物の CSS から hex を取る。**
取り方はプロジェクトのビルド構成による（例: ビルド後の出力 CSS を `--<変数名>` で grep する）。
hex を直接書いているトークンではこの問題は起きない。

取れなかった場合は「実測できていない」と書く。**近似値で合否を判定しない。**

---

## 7. トークン名が標準ユーティリティを奪う事故に注意

ユーティリティ CSS フレームワークでは、**トークン名がそのままクラス名になる**ことがある。
標準のクラス名と同じ名前でトークンを定義すると、**標準側を黙って上書きする**
（`base` `sm` `lg` `xl` `full` `none` などが衝突しやすい）。ビルドは通るので気付けない。

> 例: Tailwind v4 の `@theme` で `--color-<name>` を定義すると `text-<name>` / `bg-<name>` が生成される。

新しいカラートークンを足すときは、**使っているフレームワークの標準クラス名との衝突を先に確認する。**
