# ux-validation-planner — 検証設計と結果の振り分け

## 役割分界（重複させない）

| このスキルがやること | やらないこと（担当スキル） |
|---|---|
| 棄却しうる仮説の設計 | 数値 KPI の継続計測（`ux-measurement`） |
| 観測方法の決定 | UI の評価（`ux-design-review`） |
| 結果の層への振り分け | 下流への連鎖実行（`ux-update-cascade`） |
| — | 生の声の保存（`user-voice-ledger`） |

**なぜやるか**: 体験の原則を第一版として確定させる条件は、**現場ユーザーでの検証を1回通すこと**。

## 事前に決めること（**人間が決める。ここで停止する**）

| 項目 | 決める人 |
|---|---|
| 対象者の人数・役割 | 人間 |
| 実施時期 | 人間 |
| 実施者・記録者 | 人間 |
| 対象画面 | UX が提案してよい |

**「未定」と書き、決める人を明示して停止する。** 勝手に「5人程度」などと埋めない。

## 手順

### 1. 仮説を1つずつ書き出す

**すべてに棄却条件を付ける。付けられないものは仮説ではない。**

```
✕ この配置の方が使いやすいはず
◯ H1: コアを上部に置くと、目的の操作に到達するまでの往復が減る
   棄却条件: 3人中2人以上が、上部を経由せずに下部から操作を開始した場合
```

### 2. 既存の未検証ペインを拾う

```bash
pnpm voices query --type pain --status 未検証
```

### 3. 観測方法を決める

| 型 | 観測すること |
|---|---|
| 行動観察 | 探しに行った回数 / 手が止まった箇所 / 人に聞こうとした瞬間 / 往復・離脱 |
| フォーカス計測 | 視線・操作がどこに集まったか（骨格層の判断材料） |
| 発話 | 口に出したこと |

> ⚠️ **発話と行動を分けて記録する。** 一致しないことがある前提で扱う。
> ⚠️ **「良かったですか？」を聞く会にしない。** 感想は仮説を棄却しない。

### 4. 実施する

タスクだけ渡す。やり方を説明しない。詰まっても助けない（どこで詰まるかが観測対象）。誘導しない。

### 5. 結果を層に振り分ける

| 観測されたこと | 返す層 |
|---|---|
| コンセプトの前提が崩れた | 戦略 |
| 原則が成立しない | 要件 |
| コアが想定と違った | 構造 |
| 面積配分の優劣がついた | 骨格 |

### 6. 上流へ返す

反証は `ux-update-cascade` へ。**変わらなかった（裏付けられた）ことも記録する。**

新しく出た声は `user-voice-ledger` で逐語のまま記録する（`source: user-validation`）。

## 出力形式

```
■ 検証の目的: <何が決まれば前に進むか>
■ 段取り
   実施予定: <日付 / 未定（決める人: 人間）>
   対象者: <人数・役割 / 未定>
   実施者・記録者: <名前 / 未定>
   対象画面: …

■ 仮説
   H1: <仮説>
       出典: <spec / VOICE-xxx>
       棄却条件: <何が観測されたら捨てるか>
       観測方法: 行動=… / 発話=…

■ 停止している項目: <未定のもの。決める人 / いつまでに>
■ 記録先: pd/validations/VP-YYYYMMDD-NN-<slug>.md
```

## 禁止

- 棄却条件のない仮説を検証にかける
- 対象者の人数・時期・実施者を AI が決める
- 発話と行動を混ぜて記録する
- 誘導質問をする
- 結果を「概ね好評」で終わらせる
- 反証されたのに下流をそのままにする
