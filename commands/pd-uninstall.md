# pd-uninstall

`/pd:pd-init` がこのプロジェクトに作ったものを取り除く。

**既定では何も削除しない。** 引数が無ければ一覧を出して終わる。plugin 本体（`/plugin uninstall`）はプロジェクト側のファイルに触れないため、片付けはこのコマンドが受け持つ。

**先にこのコマンドを実行する。** plugin をアンインストールすると `/pd:pd-uninstall` も一緒に消え、後から実行できなくなる。

## 引数

| | 消すもの | 使う場面 |
|---|---|---|
| なし | **何も消さない。**該当するものを一覧表示するだけ | まず何があるか見る |
| `--keep-data` | 仕組みだけ（下記の「仕組み」）。**分析結果は残す** | pd の運用はやめるが、Note と Context は資産として残す |
| `--purge` | 仕組みと分析結果の両方 | 完全に撤去する |

## 対象

**仕組み**（`--keep-data` / `--purge` の両方で消す）

- `pd/ledger.json` / `pd/ledger-log.md` — 台帳
- `pd/.local/` — 元データの一時置き場（共有しないもの）
- `.github/workflows/validate.yml` — **pd の CI である場合のみ**。`pd-plugin` を checkout している行が無ければ他人の CI なので触らない
- `.gitignore` の `pd/.local/` の行（`.local/` のみの旧レイアウトも同様）
- `CLAUDE.md` の「pd の規約」節

**分析結果**（`--purge` でのみ消す）

- `pd/products/` `pd/analyses/` `pd/voices/` `pd/simulations/` `pd/specs/` `pd/decisions/` `pd/validations/` `pd/measurements/` `pd/reviews/`
- 旧レイアウト（root 直下に置いている場合）は同名の root 直下ディレクトリ

## 手順

1. **数える** — 上の対象それぞれについて、存在するかとファイル数を調べる。`pd/analyses/` などは `.md` の件数を出す

2. **一覧を出す** — 消える対象と、残る対象を分けて表示する。分析結果は件数を必ず添える

3. **引数が無ければここで終わる** — 「`--keep-data` で仕組みだけ、`--purge` で全部消せる」と伝えて終了する。**何も削除しない**

4. **確認を取る** — `--purge` の場合は、消える `.md` の総数を示して実行してよいか確認する。**この確認は省略しない**（追記のみで積み上げた記録は復元できない）

5. **消す** — 上の対象のうち、指定された範囲だけを削除する

   - **既存ファイルへの追記部分は、その行 / その節だけを消す。**`.gitignore` と `CLAUDE.md` のファイルごと削除は禁止。pd より前からあった内容が失われる
   - `.github/workflows/validate.yml` は、中身に `pd-plugin` の checkout がある場合のみ削除する。無ければ「pd の CI ではないため残した」と伝える
   - `--purge` で `pd/` が空になったら `pd/` 自体も削除する

6. **報告** — 消したものと、残したもの（理由つき）を分けて伝える。最後に次の1行を示す

   ```
   plugin 本体を外すには /plugin uninstall pd@pd-plugin
   ```

## やらないこと

- **git の履歴には触らない。** 消したのは作業ツリーのファイルだけで、コミット済みの記録は残る。完全に消したい場合は利用者自身が履歴を書き換える
- **他のプロジェクトには触らない。** 対象は今のプロジェクトのみ
- **plugin 本体をアンインストールしない。** `/plugin uninstall` は利用者が実行する
