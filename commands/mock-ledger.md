# pd-mock-ledger

モックで合意したものが、実装で**落ちる・色が変わる・文言が言い換わる**のを止める。

原因はいつも同じで、**モックの中身を覚えているのが会話だけ**であること。会話は次の日には残っていない。落ちたことは、落ちた側からは見えない。

だからモックと実装の間に、機械が読める1枚を挟む。

| 誰が | 何を |
|---|---|
| `scripts/mock_capture.py` | モックの HTML から文言・色・要素を**全部**抜き出す |
| 人間 | 色をトークンに対応づけ、要素に実装の目印を書く |
| `scripts/validate.py` | 実装と突き合わせ、**落ちた要素・変わった文言・直書きの色**を出す |

記録先は `pd/specs/05-surface/mocks/<名前>.md`。

## 手順

### 1. 抽出する（手で数えない）

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/mock_capture.py" <モックの.html>
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/mock_capture.py" <モックの.html> --name 検索結果
```

**読んで要約しない。** 要約はそのたびに拾う量が変わり、落ちた1行は落ちたと気づけない。

既に台帳があれば止まる。作り直すときだけ `--force`（手で埋めた対応づけは消える）。

### 2. 埋める（3箇所だけ）

| 欄 | 何を書くか |
|---|---|
| **公開** | Artifact の URL。渡していないなら `公開しない: 理由` |
| 色の表の **トークン** | `pd/specs/05-surface/design-tokens.md` にある名前。**無ければ足すか、近い既存トークンに寄せる**。ここが空だと「赤」で合意したものが実装で別の赤になる |
| 要素の表の **実装の目印** | 実装側を検索して見つかる文字列（コンポーネント名・`data-testid`・関数名） |

**捨てるなら台帳の上で捨てる。** 落とす要素・使わない文言は消さず、状態を書き換える。

| 状態 | いつ |
|---|---|
| `実装` | 実装に写す（既定） |
| `見送り: UXDR-xxx` | 落とすと決めた。**記録の無い見送りは、次の人には欠落に見える** |
| `動的: 理由` | 実行時に組み立てる文言（件数・日付・APIの返り値） |

### 3. 実装する

台帳を上から写す。文言は一字一句そのまま。言い換えたいなら**先に台帳を書き換えてから**実装する（台帳が現在の正）。

色はトークンを参照する。モックの生値（`#…`）を実装に持ち込まない。

### 4. 実装先を書いて、照合させる

台帳の `実装:` に、実装したファイルかディレクトリのパスを書く。

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/validate.py"
```

ここで出るのは次の4つ。**モックとの差は、ここでしか自動では見つからない。**

- モックの文言が実装に無い（言い換え・欠落）
- モックの要素が実装に無い（目印で探して見つからない）
- 実装が色を直書きしている
- 色がトークンに対応づいていない / そのトークンが台帳に無い

まだ実装していない段階では `実装: 未着手` のままでよい。照合は行われない。

## やらないこと

- **見た目の良し悪しの判断** — `ux-design-review`
- **トークンの値を決める** — `design-token-keeper` / `/pd:design-system`
- **落とすかどうかの意思決定** — 人間が決め、`ux-decision-record` に残す

## 注意

- 文言の照合は**空白を落として**比べる（実装では長い文言が行をまたぐ）。それでも当たらない書き方（文字列連結・変数の埋め込み）は `動的: 理由` にする
- 実装先にディレクトリを指定すると、その配下のソースを全部見る。広く指すほど「見つかったことにする」誤りが増えるので、**画面ごとのディレクトリかファイルを指す**
