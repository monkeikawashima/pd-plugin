# pd-design-system

UI/UX の作成とモック作成が**毎回同じものを参照する**ようにする。
記録先は `pd/specs/05-surface/design-system.md`（現在値・上書き）。

**決めるのは人間。** このコマンドがやるのは、候補を機械的に集めて選ばせ、答えを1箇所に固定することだけ。

## 手順

### 1. 既にあるかを見る

`pd/specs/05-surface/design-system.md` があれば、現在の種別・真実の源・決めた日を提示してから
「変更するか / このままか」を聞く。**黙って上書きしない。**

### 2. 候補を機械的に集める（聞く前に）

ゼロから聞くと答えが揺れる。**先に検出してから選ばせる。**

| 探す先 | 何が分かるか |
|---|---|
| `package.json` の依存 | 既製ライブラリ（`@mui/*` `antd` `@chakra-ui/*` `react-bootstrap` `@mantine/*` `@radix-ui/*` など） |
| `components.json` | shadcn/ui（`aliases.components` が参照先） |
| `tailwind.config.*` / `@theme` を含む CSS | Tailwind のトークン定義 |
| `.storybook/` | 一覧の見方（起動コマンド） |
| 社内 UI パッケージらしき依存 | 自前のデザインシステム |
| `pd/specs/05-surface/design-tokens.md` の真実の源 | 既に固定済みのトークン定義 |

見つからなければ「検出できなかった」とそのまま伝える。**推測で埋めない。**

### 3. 選ばせる（`AskUserQuestion`）

検出した候補に、次の2つを必ず添える。

- **自前（パスを指定する）**
- **無し（後で決める）** — 導入直後や PoC では普通の答え

> **「無し」を選べることが要。** 未記入と「無いと決めた」を区別できないと、
> UI の作業のたびに同じ確認が繰り返される。

複数を併用している場合は「併用」とし、**どちらが優先かを1行で書かせる**。
優先が決まらないものは、決まるまで種別を確定しない。

### 4. 記録する

plugin の `skills/analyze/uiux/templates/design-system.md` を Schema として
`pd/specs/05-surface/design-system.md` に**上書き**する。

- **参照先には実在するパスだけを書く。** 書いた時点で `ls` して確かめる
- 版（バージョン）は固定していなければ「未固定」と書く。**空欄にしない**
- 「無し（後で決める）」を選んだ場合も**ファイルは作る**。種別と決めた日だけが入る

### 5. トークン台帳と繋ぐ

`pd/specs/05-surface/design-tokens.md` が既にあるなら、その「真実の源」が
今回決めた参照先と食い違っていないかを確認する。食い違っていたら、
**どちらが正かを決めるまで止める**（2箇所で定義された状態を作らない）。

### 6. 変更だったときは、理由を残す

乗り換え・廃止の場合は `ux-decision-record` を使って UXDR を1件書く。
**このファイルは現在値しか持たない。** なぜ変えたかはここに残らない。

### 7. 検証

`/pd:validate` を実行し、違反が出ないことを確認してから完了を報告する。

## 報告

決めた種別・真実の源・参照先の実在確認の結果を伝える。
「無し（後で決める）」を選んだ場合は、**UI の作業時に促されること**を1行で添える。
